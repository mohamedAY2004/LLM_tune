Cheat sheet

LoRA & QLoRA

Train a small adapter instead of the whole model, and store the frozen model in 4 bits when it still doesn’t fit. Taught in Lesson 6 and Lesson 7.

The idea in one line

h = W·x + (alpha / r) · B·(A·x)

W  d_out × d_in   frozen
A  r × d_in       trainable
B  d_out × r      trainable, starts at 0
  • Adapter size per layer: r × (d_in + d_out). For 960 × 960 at r = 8: 15,360 vs 921,600.
  • B starts at zero, so at step 0 the model equals the base model.
  • Keras analogy: base.trainable = False plus a small trainable part, but the part sits inside each linear layer.

LoraConfig

from peft import LoraConfig

peft_config = LoraConfig(
    r=8,                          # rank
    lora_alpha=16,                # update scaled by alpha / r
    target_modules="all-linear",  # every linear layer but the output head
    task_type="CAUSAL_LM",

LoRA in SFTTrainer

args = SFTConfig(output_dir="lora-out",
                 learning_rate=2e-4,   # ~10x full FT (2e-5)
                 bf16=False,           # T4: no bf16
                 max_length=256, report_to="none")
trainer = SFTTrainer(model=model, args=args,
                     train_dataset=train, processing_class=tok,
                     peft_config=peft_config)
trainer.model.print_trainable_parameters()
trainer.train()

SFTTrainer calls get_peft_model for you. Don’t do both: passing a PeftModel and peft_config raises ValueError.

Observed: SmolLM2-360M, r = 8, all-linear: 4.34M trainable params (1.20%), adapter file 17.4 MB. The full model in fp32 is about 1.4 GB.

Memory math

Stored per parameterBytes1.7B model
fp32 weights46.8 GB
fp16 / bf16 weights23.4 GB
4-bit weights~0.5~0.85 GB
Full FT: weights 6 + grads 4 + AdamW 8~18~31 GB

GB ≈ params × bytes / 1e9, plus activations (batch × sequence length × layers × hidden size). LoRA pays the 18 bytes only for adapter parameters. QLoRA also stores the frozen weights in 4-bit.

QLoRA on a T4

%pip install -q -U "bitsandbytes>=0.46.1"
from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.float16)   # bf16 on Ampere+

model = AutoModelForCausalLM.from_pretrained(
    model_id, dtype=torch.float16,           # embeddings + norms
    quantization_config=bnb_config)          # lands on the GPU

args = SFTConfig(..., bf16=False, fp16=True)  # T4
trainer = SFTTrainer(model=model, args=args, ...,
                     peft_config=peft_config)

# TRL 1.15 casts 4-bit models' adapters to bf16;
# fp16 training needs them in fp32:
for p in trainer.model.parameters():
    if p.requires_grad:
        p.data = p.data.float()

Skip the upcast and fp16 training fails with NotImplementedError: "_amp_foreach_non_finite_check_and_unscale_cuda" not implemented for 'BFloat16'.

v5 removed from_pretrained(..., load_in_4bit=True). It now fails with TypeError: ... unexpected keyword argument 'load_in_4bit'.

Out of memory? Turn these knobs

  1. per_device_train_batch_size down (1–4), gradient_accumulation_steps up, so batch × steps stays the same.
  2. gradient_checkpointing=True. It’s the SFTConfig default, so check you haven’t turned it off.
  3. max_length down to fit your longest real example.
  4. Smaller r, or LoRA on fewer modules.
  5. 4-bit base model (QLoRA), or a smaller model.

Measure, don’t guess

model.get_memory_footprint() / 1e9        # model size, GB
torch.cuda.reset_peak_memory_stats()
trainer.train()
torch.cuda.max_memory_allocated() / 1e9   # training peak, GB

trainer.model.print_trainable_parameters()  # trainable / total

Counting by hand with p.numel() works for trainable parameters, but a 4-bit model’s packed weights report half their real count, so a hand-made total is wrong. Use print_trainable_parameters() for the percentage.

Observed with the Lesson 7 notebook (4 GB laptop GPU, fp16): SmolLM2-1.7B in 4-bit has a 1.01 GB footprint. QLoRA with r = 16 on all linear layers, batch 4 × 2, max_length=128 trained 18.1M params (1.05%) and peaked at 1.46 GB.
