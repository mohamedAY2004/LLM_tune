Lesson 4 · about 25 minutes

A dataset for chat

Build train and test sets for TRL, Hugging Face’s library for fine-tuning chat models, and see the exact text supervised fine-tuning trains on.

Your win today

You’ll build a 500-row training set and a 40-row held-out test set with 🤗 Datasets, render one row through the chat template, and measure every row in tokens. Lesson 5 trains on exactly this data.

From task to training set

1 · Two shapes of chat data

TRL’s SFTTrainer accepts chat data in two shapes (dataset formats). Here is one of our rows in each, with the user text shortened:

# "messages": the whole chat in one list
{"messages": [
    {"role": "user", "content": "Extract ... Text: Hi, I'm Kenji from Oslo. I'm 66."},
    {"role": "assistant", "content": '{"name": "Kenji", "age": 66, "city": "Oslo"}'}]}

# prompt-completion: the same chat, split where the answer starts
{"prompt":     [{"role": "user", "content": "Extract ... Text: Hi, I'm Kenji from Oslo. I'm 66."}],
 "completion": [{"role": "assistant", "content": '{"name": "Kenji", "age": 66, "city": "Oslo"}'}]}

When I rendered both shapes through the chat template, the text was identical. The difference is which tokens the loss counts. By default, SFTTrainer computes the loss on the whole messages sequence, system prompt and user message included. For prompt-completion rows it computes the loss on the completion only (SFT docs). That’s your Lesson 3 mask, for free, and it’s why the course’s make_rows returns prompt-completion rows.

This is the training text for that row. The highlighted part is the completion, the only part the loss counts:

<|im_start|>system
You are a helpful AI assistant named SmolLM, trained by Hugging Face<|im_end|>
<|im_start|>user
Extract the person's name, age and city as JSON.

Text: Hi, I'm Kenji from Oslo. I'm 66.<|im_end|>
<|im_start|>assistant
{"name": "Kenji", "age": 66, "city": "Oslo"}<|im_end|>

Notice the closing <|im_end|> (and the newline after it) is part of the completion. Training on it is what teaches the model to stop after the JSON.

2 · A test set the model has never seen

A held-out test set is data the model never trains on. Ours goes further. make_rows(n, "test") draws from a separate pool of 5 names, 4 cities and 2 phrasings that never appear in training. In the notebook, the two splits share no names and no cities.

Keras: a slice of the same data

model.fit(x, y, epochs=5,
          validation_split=0.2)
# validation = the last 20% of x, y:
# same names, cities, phrasings

This course: a separate pool

train = Dataset.from_list(
    make_rows(500, "train", seed=0))
test = Dataset.from_list(
    make_rows(40, "test", seed=1))
# test: unseen names, cities, phrasings

Keras picks validation rows “from the last samples in the x and y data provided, before shuffling”. Keras fit docs. Why bother? If test rows reused training names and phrasings, a model that had memorised “Kenji from Oslo” would look perfect. With unseen inputs, a high score means the skill generalises: read a new sentence, copy three fields into strict JSON.

3 · 🤗 Datasets in three moves

  • Dataset.from_list(rows) turns a list of dicts into a table with one column per key: prompt and completion.
  • Indexing: train[0] is one row (a dict), train["completion"] is a column, train[:2] is a dict of lists.
  • train.map(fn) runs fn on every row and adds the keys of the dict it returns as new columns. It returns a new dataset, so assign it: train = train.map(fn).

SFTConfig’s max_length defaults to 1024, and its truncation mode is "keep_start". SFTConfig reference. You’ll use map to count each row’s tokens after templating. When I ran it, training rows were 77–91 tokens and test rows 83–90. That sets max_length in Lesson 5. The trainer cuts longer rows from the end, and the end is the answer. With max_length=80, the Kenji row’s trained tokens became {"name": "Kenji", "age": 66, "city": "Os. There’s no closing brace and no <|im_end|>, so the model never learns to stop. Lesson 5 uses 256, with plenty of room.

Practice

1. Why does this course store its rows as prompt-completion instead of messages?

  1. By default the loss covers only the completion
  2. The messages shape cannot hold an assistant reply
  3. Prompt-completion rows skip the chat template at training
  4. Prompt-completion rows train in about half the time

2. Every test name, city and phrasing is missing from the training set. What does a high test score show?

  1. The model learned the skill, not the rows
  2. The model memorised all five hundred training rows
  3. The training loss went all the way down
  4. A random split would give the same evidence

3. Your longest row is 91 tokens and you set max_length=80. What happens to that row in training?

  1. It loses the end of its JSON answer
  2. It loses the system prompt at its start
  3. The trainer raises an error before training starts
  4. It is split into two shorter training rows

4. Review (Lesson 3): you train with unmasked labels, so every token counts. What happens to the loss on the prompt tokens?

  1. It falls: the model learns to predict it
  2. It stays put, because the prompt never changes
  3. It rises, because the answer gets more weight
  4. It drops to zero, since -100 skips it

5. add_length is defined as in the notebook. Put the lines in order to build the training set and check that its longest row fits. Two lines don’t belong.

  1. rows = make_rows(500, "train", seed=0)
  2. train = Dataset.from_list(rows)
  3. train = train.map(add_length)
  4. longest = max(train["n_tokens"])
  5. print("fits in 256:", longest <= 256)
  6. rows = make_rows(500, "test", seed=0)
  7. train.map(add_length)

Building training rows from the "test" split would put the held-out names and phrasings into training, so the test set would no longer measure generalisation. A bare train.map(add_length) throws its result away, because map returns a new dataset rather than changing train in place. The next line would then fail: there’s no n_tokens column.

6. From memory: an interviewer asks, “How would you build the test set for a fine-tuned extractor, and why not just hold out 10% of your training rows?” Answer in two or three sentences.

I’d build test rows from inputs the model never trains on: different names, places and phrasings, ideally written separately from the training data. A random 10% split shares the training set’s names and templates, so a model that memorised them could score high without learning the skill. A truly separate set measures generalisation, which is what real users will test.
