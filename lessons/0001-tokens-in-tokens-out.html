Lesson 1 · about 25 minutes

Tokens in, tokens out

Load a chat model with Hugging Face, see exactly what it reads, and watch it fail at the task you’ll fine-tune it for.

Your win today

In a Colab notebook you’ll load SmolLM2-135M-Instruct, print the exact string it reads, predict its next token by hand, and generate a reply. Then you’ll check whether that reply is valid JSON. That check is the first measurement for your capstone.

The Keras picture you already have

You’ve done transfer learning in Keras: load a pretrained network, push inputs through its matching preprocessing, read the output. Hugging Face works the same way, with two differences. The “preprocessing” is a tokenizer, and the output is a score for every token in the vocabulary, not one class per image.

PyTorch + Hugging Face — chat LLM

from transformers import AutoTokenizer, AutoModelForCausalLM

tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id)
inputs = tok.apply_chat_template(
    messages, add_generation_prompt=True,
    return_tensors="pt", return_dict=True)

with torch.no_grad():
    logits = model(**inputs).logits  # (batch, seq, vocab)
next_id = logits[0, -1].argmax()     # next token

The Auto* classes read the checkpoint’s config.json and build the right architecture for you: LlamaForCausalLM for SmolLM2. Auto classes docs. The tokenizer and the model are a matched pair. Always load both from the same checkpoint id. A token id is just a row number in the model’s embedding table, so a tokenizer from another model points at the wrong rows. Nothing crashes, but the output is garbage.

The pipeline, end to end

messageslist of dicts→ chat templateone string→ input_ids(1, 49)→ modelforward pass→ logits(1, 49, 49152)→ argmax at last positionnext token↻ append & repeat= generate()

1 · The chat template is what the model actually reads

A chat model never sees your list of messages. The tokenizer’s template flattens the conversation into one string, with special tokens marking who is speaking. This is what SmolLM2 actually read when I ran it:

<|im_start|>system
You are a helpful AI assistant named SmolLM, trained by Hugging Face<|im_end|>
<|im_start|>user
Extract the person's name and city as JSON: 'Hi, I'm Sara from Cairo.'<|im_end|>
<|im_start|>assistant

Each model family has its own template, stored with its tokenizer. So call the tokenizer’s template; never build the string by hand. Chat templates docs. Three things to notice. First, a system prompt you didn’t write was added by the template. Second, every turn is wrapped in <|im_start|>…<|im_end|>. Third, add_generation_prompt=True appended the final <|im_start|>assistant line, which tells the model it’s its turn.

This matters for fine-tuning because fine-tuning data has to go through the same template the model sees at inference. Training on a different format is one of the most common supervised fine-tuning (SFT) bugs, and it fails silently.

2 · Logits: a classifier at every position

The forward pass returns logits of shape (batch, sequence, vocab). In our case that’s (1, 49, 49152): for each of the 49 positions, a score for every one of the 49,152 tokens in the vocabulary as the next token. In Keras terms, it’s a Dense(vocab_size) head applied at every timestep.

Lesson 2 builds on this: training is cross-entropy between these logits and the token that actually came next, at every position. To predict what comes after the prompt, read the last position and take the argmax. generate() does exactly that in a loop: pick a token, append it, run again. It stops at the end-of-turn token (<|im_end|>) or at max_new_tokens. Text generation guide.

torch.no_grad() also saves memory: nothing is stored for a backward pass. model(**inputs) unpacks the dict, so it’s the same as model(input_ids=…, attention_mask=…). You’ll see this ** idiom everywhere in Hugging Face code.

Two Transformers v5 notes. Pass return_dict=True to apply_chat_template: v5 returns a dict anyway, but many older tutorials got a bare tensor. And from_pretrained now loads the checkpoint’s saved precision, bfloat16 for SmolLM2 (v5 migration guide). The free Colab T4 has no native bfloat16 (bf16) support, and the model is tiny, so the notebook asks for full precision: dtype=torch.float32. Older code calls this argument torch_dtype.

Practice

1. You load a tokenizer from checkpoint A and a model from checkpoint B. What’s the most likely result?

  1. Token IDs map to wrong embeddings
  2. Transformers converts the vocabulary for you
  3. Generation runs slower but stays correct
  4. The chat template gets silently ignored

2. logits.shape is (1, 49, 49152). What does 49152 represent?

  1. Scores for every token in vocabulary
  2. Number of tokens in the prompt
  3. Hidden size of each transformer layer
  4. Maximum context length of the model

3. Why does the chat template matter so much for fine-tuning?

  1. Training text must match inference format
  2. It makes tokenization run much faster
  3. It removes the need for labels
  4. It lowers memory use during training

4. What does the tensor returned by model.generate(**inputs) contain?

  1. The prompt IDs plus generated IDs
  2. Only the freshly generated token IDs
  3. Decoded text of the full reply
  4. Logits for each newly generated token

5. The model and tokenizer are already loaded. Put the lines in order to get a clean reply. Two lines don’t belong.

  1. messages = [{"role": "user", "content": prompt}]
  2. inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt", return_dict=True).to(device)
  3. out_ids = model.generate(**inputs, max_new_tokens=80, do_sample=False)
  4. new_ids = out_ids[0, inputs["input_ids"].shape[1]:]
  5. reply = tok.decode(new_ids, skip_special_tokens=True)
  6. inputs = tok(prompt, return_tensors="pt")
  7. model.compile(optimizer="adam")

Calling tok(prompt) on raw text skips the chat template. You get bare tokens like ['Hi', 'Ġthere'] with no <|im_start|> markers, so the model never sees the turn structure it was trained on. compile is Keras thinking: PyTorch models have no compile/fit step. You’ll write the training loop yourself in Lesson 2.

6. From memory: you’re in an interview and asked “What does a causal LM output, and how does generate() use it?” Answer in two or three sentences.

It outputs logits of shape (batch, seq, vocab): at every position, a score for each vocabulary token as the next token. Effectively it’s a softmax classifier at every timestep. generate() takes the logits at the last position, picks a token (argmax for greedy, or sampling), appends it to the sequence, and repeats until an end-of-turn token or max_new_tokens.
