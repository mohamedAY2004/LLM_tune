Supervised fine-tuning with TRL

1 · SFTTrainer is Lessons 2 and 3, automated

Supervised fine-tuning (SFT) means training on input–output pairs you wrote: here, a message and its ideal JSON. You already know every step; SFTTrainer runs them for you (TRL SFT docs):

Step (where you met it)Where SFTTrainer does it
Render the chat with apply_chat_template (Lessons 1, 4)When you build the trainer, for every row
Mask prompt tokens with -100 (Lesson 3)The labels column it builds for prompt-completion rows
Pad a batch; pad labels with -100 (Lesson 3)Its data collator: the function that builds each batch
Forward, loss.backward(), optimizer.step(), zero_grad() (Lesson 2)trainer.train(), with AdamW and a linearly decaying learning rate by default

You’ll check the mask in the notebook. For the first row, the tokens whose label isn’t -100 decoded to exactly the completion, {"name": "Kenji", "age": 66, "city": "Oslo"}<|im_end|> plus a newline.

2 · The SFTConfig arguments that matter

SFTConfig holds the training settings, like the arguments to Keras compile and fit:

Keras

model.compile(
    optimizer=keras.optimizers.AdamW(5e-5),
    loss="sparse_categorical_crossentropy")

model.fit(x, y,
          epochs=1,
          batch_size=8)

TRL

args = SFTConfig(
    output_dir="sft-smollm2-135m",
    learning_rate=5e-5,
    num_train_epochs=1,
    per_device_train_batch_size=8,
    max_length=256, bf16=False,
    logging_steps=10, save_strategy="no",
    report_to="none")
trainer = SFTTrainer(model=model, args=args,
    train_dataset=train, processing_class=tok)
trainer.train()
# no loss argument: the model computes
# cross-entropy from the labels
ArgumentWhy this value
learning_rate=5e-5Default 2e-5. 5e-5 learned this task in one epoch.
num_train_epochs=1The default is 3. One pass (63 steps) was enough.
per_device_train_batch_size=8Keras’s batch_size: rows per step on each GPU.
max_length=256The longest row is 91 tokens (Lesson 4). Nothing gets cut.
bf16=FalseOn by default, but the T4 has no native bf16. We train in fp32.
logging_steps=10, save_strategy="no", report_to="none"Log every 10 steps; save no checkpoints; use no external tracker.

Old tutorials use two retired names: max_seq_length (now max_length) and tokenizer= (now processing_class=). On TRL 1.15, both raise a TypeError; I checked.

3 · Read the log, then trust the test set

Here is my run, printed from trainer.state.log_history:

step  10 | loss 0.04627 | mean_token_accuracy 0.990
step  20 | loss 0.00085 | mean_token_accuracy 1.000
step  30 | loss 0.00028 | mean_token_accuracy 1.000
step  40 | loss 0.00018 | mean_token_accuracy 1.000
step  50 | loss 0.00016 | mean_token_accuracy 1.000
step  60 | loss 0.00014 | mean_token_accuracy 1.000

Colab’s progress table shows only the training loss. The notebook prints the other metrics from trainer.state.log_history. loss is the cross-entropy on the unmasked (completion) tokens, averaged over each 10-step window. mean_token_accuracy is the share of those tokens whose top prediction was right (logged metrics). Both come from training rows, so they show fit, not generalisation.

That’s the job of score on the 40 held-out rows:

valid-JSON ratefield accuracya typical reply
Base model0.0250.025JSON:\n{\n "name": "Amara", ...
Fine-tuned1.01.0{"name": "Amara", "age": 54, "city": "Hanoi"}

A field only counts when the reply parses as JSON, so the base model scores low on both despite finding the right content. SFT taught it the format, and to stop. This task is easy, so a perfect score comes fast; Lesson 8 hunts for inputs that still break it.

Practice

1. After 20 steps the loss is 0.00085 and mean_token_accuracy is 1.0. What does that tell you?

  1. The model fits its training rows well
  2. It will be perfect on new text
  3. The learning rate is far too high
  4. The prompt tokens were not masked out

2. Why does the notebook pass bf16=False to SFTConfig on a Colab T4?

  1. The T4 has no native bf16 support
  2. The T4 needs fp32 for full fine-tuning
  3. On a T4, bf16 breaks chat templates
  4. On a T4, bf16 disables completion-only loss

3. Which SFTConfig argument plays the role of Keras fit(batch_size=8)?

  1. per_device_train_batch_size
  2. gradient_accumulation_steps
  3. per_device_eval_batch_size
  4. dataloader_num_workers

4. Review (Lesson 4): you run train.map(add_length) but don’t assign the result. What does train hold now?

  1. The original rows, with no n_tokens column
  2. The original rows plus an n_tokens column
  3. Only the n_tokens column, with nothing else
  4. An empty dataset, because map consumed it

5. model, tok, args and test_rows are ready. Put the lines in order to fine-tune and score. Two lines don’t belong.

  1. rows = make_rows(500, "train", seed=0)
  2. train = Dataset.from_list(rows)
  3. trainer = SFTTrainer(model=model, args=args, train_dataset=train, processing_class=tok)
  4. trainer.train()
  5. after = score(trainer.model, tok, test_rows)
  6. trainer = SFTTrainer(model=model, args=args, train_dataset=train, tokenizer=tok)
  7. args = SFTConfig(output_dir="out", max_seq_length=256)

Both distractors use names from older tutorials. In TRL 1.15, tokenizer= is now processing_class=, and max_seq_length is now max_length. Each old name raises a TypeError. Besides, args was already ready.

6. From memory: an interviewer asks, “You give SFTTrainer a prompt-completion row. What happens to it before the optimizer step?” Answer in three or four sentences.

The trainer renders prompt plus completion through the tokenizer’s chat template and tokenizes it. It also tokenizes the prompt alone to find where the completion starts, and builds labels as a copy of the input ids with every prompt position set to -100. The collator pads the batch, padding labels with -100 too. Then it’s the Lesson 2 loop: a forward pass gives the cross-entropy over the completion tokens only, then backward, an AdamW step, and zeroed gradients.
