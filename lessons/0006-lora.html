Lesson 6 · about 25 minutes

LoRA: train 1% of a bigger model

Freeze the model, train a few small matrices inside it, and match a full fine-tune.

Your win today

You’ll fine-tune SmolLM2-360M-Instruct, almost 3× the size of Lesson 5’s model, while training about 1% of its parameters. It should match your Lesson 5 full fine-tune on the held-out test set, and the file you save is only about 17 MB.

Freeze the model, train a little beside it

1 · The LoRA idea

You know this move from Keras transfer learning: set base.trainable = False and train a small head on top. LoRA (Low-Rank Adaptation) also freezes the pretrained model. But the trainable part isn’t a head on top. It’s a small side path inside the model’s linear layers (PyTorch’s name for a Keras Dense layer). These side paths are called an adapter.

The LoRA paper froze GPT-3’s weights and trained only these “rank decomposition matrices”, cutting trainable parameters by 10,000× with no extra latency at inference. Its §4.1 defines A, B, the zero start and the alpha / r scaling. Hu et al. 2021. For a frozen weight matrix W, LoRA learns two thin matrices, A and B, and adds their product to the layer’s output:

h = W·x + (alpha / r) · B·(A·x)        # W frozen; only A and B train

The rank r is small: 8 today. Take one 960 × 960 attention projection in SmolLM2-360M. W holds 921,600 numbers. A (8 × 960) and B (960 × 8) together hold 15,360, about 1.7%. B starts at zero, so before the first training step the model behaves exactly like the base model.

Keras — freeze, add a head

base = keras.applications.ResNet50(
    weights="imagenet", include_top=False)
base.trainable = False          # freeze

model = keras.Sequential([
    base,
    keras.layers.GlobalAveragePooling2D(),
    keras.layers.Dense(10),     # trains
])

PEFT + TRL — freeze, add adapters inside

from peft import LoraConfig

peft_config = LoraConfig(
    r=8, lora_alpha=16,
    target_modules="all-linear",
    task_type="CAUSAL_LM")

trainer = SFTTrainer(model=model, args=args,
    train_dataset=train, processing_class=tok,
    peft_config=peft_config)  # freezes + adds A, B

2 · LoraConfig: four arguments and a bigger learning rate

ArgumentWhat it doesToday
rRank of A and B. The adapter’s size grows in proportion to it.8
lora_alphaScales the update by alpha / r. A common choice is 2 × r.16
target_modulesWhich layers get adapters. "all-linear" means every linear layer except the output head."all-linear"
task_typeTells PEFT what kind of model it is wrapping."CAUSAL_LM"

“LoRA Without Regret” (Thinking Machines, 2025) found LoRA on all layers far better than attention-only, and the best LoRA learning rate consistently about 10× the full fine-tuning one. The PEFT LoRA guide defines "all-linear". Pass the config to SFTTrainer with peft_config=. The trainer freezes the model, inserts the adapters and trains only them. Apart from the checkpoint id and peft_config=, the one other change to your Lesson 5 code is the learning rate. The TRL PEFT docs recommend about 10× the full fine-tuning rate for LoRA: 2e-4, next to TRL’s full fine-tuning default of 2e-5. (Lesson 5 used 5e-5.)

3 · What you save is an adapter

LoRA also saves training memory. Gradients and AdamW’s extra state exist only for trainable parameters, so the frozen 99% costs no optimizer memory. Lesson 7 turns that into numbers. After training, trainer.model.save_pretrained(folder) writes adapter_config.json (your LoraConfig) and adapter_model.safetensors (just the A and B matrices), plus a README.md stub. That’s your whole fine-tune: about 17 MB, against about 1.4 GB for the full model in fp32. To use it, you load the base model and attach the adapter. Lesson 9 merges the two into one model for the Hub.

Practice

1. After SFTTrainer wraps your model with LoRA, which weights does the optimizer update?

  1. Only the small A and B matrices
  2. All the weights, but with smaller steps
  3. Only the final output head on top
  4. Only the attention layers, not feed-forward ones

2. Your LoRA run used learning_rate=2e-5, and the loss barely moved in one epoch. What should you try first?

  1. Raise the learning rate about tenfold
  2. Increase the adapter rank to 256
  3. Add the output head to target_modules
  4. Load the base model in bfloat16

3. What is inside adapter_model.safetensors after save_pretrained?

  1. Only the trained LoRA matrices, nothing else
  2. The full fine-tuned model, merged and ready
  3. The tokenizer and the chat template files
  4. Optimizer state for resuming the training run

4. Review (Lesson 5): which number shows that fine-tuning worked on inputs the model never saw?

  1. Its score on the held-out test rows
  2. Its final training loss in the log
  3. Its token accuracy on the training rows
  4. Its score on rows sliced from training

5. model, args (with the LoRA learning rate), train and tok are ready. Put the lines in order to LoRA-fine-tune, save the trained adapter, then measure its file. Two lines don’t belong.

  1. peft_config = LoraConfig(r=8, lora_alpha=16, target_modules="all-linear", task_type="CAUSAL_LM")
  2. trainer = SFTTrainer(model=model, args=args, train_dataset=train, processing_class=tok, peft_config=peft_config)
  3. trainer.train()
  4. trainer.model.save_pretrained("smollm2-360m-json-lora")
  5. size_mb = os.path.getsize("smollm2-360m-json-lora/adapter_model.safetensors") / 1e6
  6. model.trainable = False
  7. model = get_peft_model(model, peft_config)

model.trainable = False is Keras thinking. PyTorch modules have no trainable switch, so this just sets an unused attribute. PEFT freezes the model for you by setting requires_grad=False on every base parameter. get_peft_model is what SFTTrainer calls for you when you pass peft_config. Doing both raises a ValueError, because the model is already a PeftModel.

6. From memory: in an interview you’re asked, “What is LoRA, and why does it need less memory than full fine-tuning?” Answer in two or three sentences.

LoRA freezes the pretrained weights and adds a trainable low-rank update beside each targeted linear layer, so the layer computes W·x + (alpha/r)·B·A·x with small matrices A and B. Only A and B (about 1% of the parameters) get gradients and AdamW state, and that’s where most training memory goes, so memory drops and the saved adapter is a few MB. B starts at zero, so training starts exactly from the base model.
